## 3. 核心发现（对比 003）

1. **判定器修复是真实有效的**：search direct 20% → **0%**（凭常识命中关键词的假阳性清零）；chain 三策略全部 100%（验算尾段误伤消除）；subagent 类 subagent 策略 45% → **97%**（spawns 结构检查误伤消除）。003 中"subagent 无用（45%）"的结论**部分源于判定器误伤**，在正确判定下 subagent 策略并不差——只是依旧最贵。
2. **模型变更是主要混杂因素**：deepseek-v4-flash 整体强于 deepseek-chat（search react 82%→95%、subagent 类 react 92% 保持、math direct 也有一次真实算错 97%）。004 的正确率提升无法归因于"判定器修复"或"模型变更"单一因素。
3. **自适应 Policy 的价值首次被基线量化**：p0 92.5% vs always-direct 77.5%，高出 15pp（003 仅 5pp），一致率指标现在有区分度了（#19 的退化基线表提供了参照系）。
4. **"direct 默认"的结论在更强模型下更稳固**：除 search 外全部 95-100%，且 1 次调用；大数乘法（math-02）direct 5/5 但分类器仍倾向 react（4/5）——分类偏差与模型能力脱节。
5. **subagent 策略"贵"的结论稳如磐石**：search 类 8.5 次调用/23.7s，subagent 类 7.0 次/46.9s（std 52s）。正确率虽不差，但性价比依旧垫底；真正需要它的任务（长文档分块、并行调研）评测集仍未覆盖。

## 4. 局限（诚实声明）

1. **模型变更与判定器修复叠加**：无法对正确率变化做单因素归因；如需干净对比应固定模型重跑 003 基线。
2. **单模型**（deepseek-v4-flash），结论不具跨模型泛化性。
3. 关键词 + grounding 判定仍是近似（5-gram 引用校验对轻度改写敏感，可能漏判正确引用）。
4. subagent 适用域仍缺真实场景任务。
5. 全量耗时 ~70min（1200+ 次调用，4 workers，v4-flash 推理较慢）；并行分类已消除"相加"瓶颈，但总时长仍受模型延迟主导。

## 5. 下一步候选

1. **固定模型、双判定器对比**：同一模型下用旧/新判定器各跑一遍，把"判定器修复"与"模型变更"分开归因
2. 为 eval 增加 **LLM-as-judge** 判定器，对比关键词/grounding 的误判率
3. 加入真正需要 subagent 的任务（长文档分块/并行调研），回答"subagent 到底有没有用武之地"
4. 分类稳定性专项：math-02/math-06 的 20-40% 成功率（#14 修复后仍有分类降级）
